# 多平台发布 — 官方浏览器栈驱动

发布不碰平台私有 API、不逆向签名——agent 用 `mcp__playwright-mcp__browser_*` 工具在**用户自己的浏览器**里像人一样点发布流程。

## 机制（为什么这算"模拟真人"）

- **CDP attach 模式**：用户先手动开 Chrome（带 `--remote-debugging-port=9222` + 自己的用户目录），插件配置 `mode: attach / endpoint: http://127.0.0.1:9222`。agent 拿到的就是用户真实浏览器——登录态、cookies、指纹全天然，平台看到的是"这个人在操作"
- **launch 模式**（隔离实例，无登录态）：只用于采公开页面，不能发布
- 登录是**一次性人工动作**：用户在 attach 的浏览器里扫码登录一次目标平台，会话一直在；agent 每次发布前先开创作者后台检查登录态，掉了就提示用户重扫，不自己绕

## 发布流程（通用骨架）

1. `browser_navigate` 到目标平台创作者后台（下表）
2. `browser_snapshot` 看登录态：跳登录页 → 停下来让用户扫码，别继续
3. `browser_file_upload` 传视频/图片（上传控件是 input[type=file] 就直接喂文件路径）
4. `browser_type`/`fill_form` 填标题/简介/标签（标题字数各平台有上限，见下表）
5. 定时发布选平台后台的"定时/预约"控件；没有就立即发
6. **发布前最后一步停下来给用户确认**——发布是不可逆的公开动作，确认后再点提交
7. 提交后 snapshot 记下结果页/作品链接回执

## 硬规则

- **发布=用户可见的公开动作**：点"发布/提交"前必须停下给用户确认文案+平台+封面，不许自作主张发
- 登录态掉了 → 提示用户重扫，**不碰验证码、不绕风控**
- 不保存/不导出用户 cookie 和凭证
- 单平台失败如实报告（附 snapshot 证据），不静默重试刷屏——平台会判定异常操作
- 模拟真人的边界：我们只是"在真人浏览器里点 UI"，不做养号、不做批量注册、不刷量

- ✅ 机制链路已验：playwright-mcp 挂载后 23 个 browser_* 工具可用，真驱动 Chrome 打开页面+跑 JS+截图（launch 模式）
